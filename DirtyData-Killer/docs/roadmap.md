# 开发路线图：从 Skill 到 Streamlit Agent

## 当前 v0.1.0：可发布的 Prompt Skill 项目

- 三个 `SKILL.md`，支持直接复制为 Prompt。
- 成绩、销售、问卷九组输入与预期输出。
- 销售 Pandas 参考脚本、测试、跨平台说明。
- 尚无通用的自动全量诊断模块；不能把 Prompt 推断当作程序统计。

## v0.2：可重复执行的数据质量规则引擎

- `src/dirtydata/reader.py`：CSV/XLSX 读取、编码与保留列类型。
- `src/dirtydata/checks/`：缺失、重复、类型、日期、值域、格式。
- `src/dirtydata/schemas.py`：稳定 JSON/Pydantic 质量报告结构。
- `tests/`：可重复的样本断言、极端输入与文件权限处理。
- 显式拆分“错误”与“待确认风险”，明确异常记录数口径。

## v0.3：Streamlit GUI

- 上传/预览 → 诊断报告 → 勾选清洗建议 → 确认影响行数 → 导出结果与日志。
- 前端不直接编造统计，所有数字来自规则引擎。
- 原始数据只在本地/合规受控环境处理；高风险操作提供撤销与预览。

## v0.4：可选 LLM Agent

- 模型只生成*建议的操作计划*，不直接对全量数据自由执行 `eval` / 未审查代码。
- 使用结构化接口完成三步：`audit()` → `suggest()` → `apply(approved_actions)`。
- 规则引擎执行确定性工作，用户审批可破坏性动作。
- 明确密钥、日志、脱敏、上传授权和成本上限。

## 衡量指标

- 学生/运营是否能在 3 分钟内得到可理解的中文质量报告？
- 同样的测试数据，不同 AI 是否能复现主要问题？
- 真实数据错误被误删除的比例是否为零（默认零删除）？
- Issue 中出现最多的中文数据问题是什么？

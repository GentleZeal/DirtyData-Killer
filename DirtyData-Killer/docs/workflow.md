# 三个 Skill 串联：从发现问题到生成代码

三个 Skill 可以独立运行；若串联，推荐将**上一步输出的 YAML**作为下一步的输入。它只是人类可读交接约定，**不是已实现的 API**。

## Step 1：数据质量检查

把 [Prompt ①](../prompts/data-quality-audit.md) 交给聊天 AI，再发：

```text
请诊断这份销售CSV。字段有订单号、商品名称、金额、下单日期、备注。
重点：金额解析、重复订单、中文日期、Excel公式风险、商品名空格。
负数可能是退货，0元可能是赠品；只读，不要修改文件。
请在输出末尾提供schema_version固定为'0.1'的YAML交接摘要。
```

给它 [sales.csv](../examples/samples/sales.csv) 或复制数据。预期：一份报告，列出证据、严重度、优先级、待确认。

## Step 2：智能清洗建议

把 [Prompt ②](../prompts/smart-cleaning-advisor.md) 交给聊天 AI，并粘贴 Step 1 的完整报告（或 YAML）：

```text
请根据上述Q01~Q09的发现制定清洗计划，按A（可安全执行）、B（只标记）、
C（需人工决策）分类。保留源数据，不执行，不自动删除任何行。
请输出Pandas代码思路、风险、验收规则、schema_version固定为0.1的交接YAML。
```

预期：字段级动作表，例如保留原字段、日期/金额新增派生列、重复订单只标记、退款口径需确认。

## Step 3：清洗代码生成

把 [Prompt ③](../prompts/pandas-cleaning-generator.md) 交给聊天 AI，并粘贴 Step 2 的方案：

```text
根据这份已经确认的清洗方案生成完整clean.py，支持CSV/XLSX，
添加argparse、中文注释、输出目录、防覆盖检查、错误处理、异常清单与summary.json。
不许删除原记录，订单号保留前导零；未实际运行时不要声称通过测试。
```

预期：**完整代码**（而不是零散片段）与执行命令。审阅后在本地测试虚构数据；不要直接处理生产数据。

## 收尾复核（无需所有用户都做）

- [ ] 问题行数、CSV行号与证据一致；引用了第6个物理行时，检查是不是有5条数据记录
- [ ] 区分“影响记录数”与“问题项目数”，不能相加就当总异常行数
- [ ] 不擅自删主键重复行 / 成绩越界行 / 退货行
- [ ] 保留学号和订单号前导零
- [ ] 代码不会覆盖原文件，可说明如何回滚
- [ ] 案例使用虚构或脱敏数据
